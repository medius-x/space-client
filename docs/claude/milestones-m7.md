# Вехи: спайк и M7 — решения

## Вердикт спайка: GO
Цели доказаны на живом сервере без его изменения: голос через SFU (Janus) из Electron двусторонний; стерео шар-звука — тест Tone L→R, противоположный канал на цифровой тишине, fmtp-цепочка `stereo=1` до decode ch=2; per-user громкость и громкость шара независимы (playout через `<audio>`, буст ≤100%); системный звук = getDisplayMedia `audio:'loopback'`, ноль WASAPI; APM чистый (физическую петлю мик↔динамик AEC не берёт — задокументировано). Итог: NO-GO из oak-client (headless-ADM webrtc-java) в Electron работают end-to-end — обоснование полной переписи.

## Каркас лэйаута
MainScreen владеет лэйаутом: [рейл + каналы] + чат + MembersPane СПРАВА (скрыт в dmMode/звонке/room view); поверх левых колонок нижний оверлей voiceBar (при живом голосе) над userBar; клик по статус-строке voiceBar = toggleRoomView (`roomViewOpen` в appStore); userBar: аватар+ник+STOMP-статус + ⚙ единственная кнопка (аватар-редактор в Settings → General). Фолбэк-аватар — палитра user-palette (djb2 % 12), красит и ник автора. Иконки @mdi/font (`npm run icons`; нет mdi-settings в MDI 7.x). Нативная ОС-рамка окна — СОЗНАТЕЛЬНО (borderless oak = потеря Aero Snap).

## ServerSettings (RBAC-UI)
Гейт canManageAnySettings = MANAGE_ROLES||MANAGE_MEMBERS||KICK||BAN||MANAGE_CHANNELS. Overview: `PATCH /api/server {name}`. Roles: «+» сразу POST «New role N»; reorder ↑/↓ (drag — отступление) → `PUT /roles/order`; color на PATCH безусловен (null = сброс). Members: ОДИН список `GET /api/members` с banned-флагом (отдельный /bans давал дубль); BANNED-бейдж + Unban; owner disabled. Permissions канала: tri-state циклер Inherit→Allow→Deny; `PUT /overrides/{roleId} {allow[],deny[]}` — ПОЛНАЯ замена (neutral = вне множеств, DELETE = сброс к роли). Access (Public/Locked/Hidden) — ИНФЕРС из @everyone-deny (hidden = deny VIEW; locked = deny READ/SEND/ADD_REACTIONS | CONNECT/SPEAK); математика `logic/channel-access.ts`, unmanaged-биты переживают. Live: `/topic/roles|members` → refreshPermissions; оверрайды → `/topic/channels.changed` → refetch+гейтинг; сервер кикает из голоса потерявших CONNECT.

## UserSettings
Audio/Video/Appearance/Notifications — STAGED: черновик `useStagedSettings`, Apply коммитит (setSinkId и живые эффекты), уход без Apply = сброс; General/Account/Connections — immediate; General и Account — server-scoped, остальные client. Account: ротация ключевой пары БЕЗ рестарта WS; rename не закрывает окно. Connections read-only (`connectionHost:connectionPort` из GET /api/server).

## Кросс-инстанс агрегация
Друзья/DM — списки по ВСЕМ инстансам (`logic/social-aggregation.ts`): сортировка по имени БЕЗ дедупа (одно имя на двух серверах = два человека) и по свежести. Снапшоты неактивных записей в СТОРЕ `socialDirectory`: массив КЕШИРУЕТСЯ в поле, пересборка только в apply/drop — свежий массив из getSnapshot() рвёт useSyncExternalStore (бесконечный ре-рендер). Переход на чужой инстанс: openDm/ChannelOnInstance → pendingOpen* в appStore, `consumePendingOpen` ПОСЛЕ старта сессии; аватары чужих — `Avatar session:null`. Бейджи рейла: серый = unread, красный = mention; активный сервер = живой readStateStore МИНУС DM-каналы.

## Уведомления
Эффективный mention = ОДНА формула для звука/рамки/бейджа: USER-by-id / ROLE-held / DM / unsuppressed @everyone-@here; матч ПО ID (`MentionIdentity {userId, roleIds}` из ростра; до ростера ничего не матчится). Своё сообщение не бампит unread/тост (STOMP-эхо гонит REST-эхо при !isLoaded). OS-баннер — только эффективные mentions; дефолт per-server = MENTIONS (oak: ALL — отступление). Превью НЕ срезает @ники (отступление от oak), светятся только пинги ПОЛУЧАТЕЛЯ. UI-звук следует спикеру: AudioContext.setSinkId (нет в TS-lib — структурный feature-detect). Стук входа/выхода — ЕДИНЫЙ звуковой тумблер. ackActiveChannel() ДО patch при смене чата; badgeEnabled гейтит только отрисовку.

## Звонки 1-на-1
Звонок НЕ занимает чат (oak): CallPane удалён; ringing = карточка в тост-окне, accepted = та же voiceBar + RoomView с 2 плитками. Карточка: `ToastShowPayload {kind: message|call|call-status|call-end}`, без TTL; кнопки IPC `toast:callAction`; живая карточка глушит тосты. У caller'а НЕТ экранной карточки (отступление); честная фаза connecting (oak: IN_CALL сразу); кнопки Camera нет (камера = источник в шар-пикере); Accept НЕ открывает call view (авто-открытие убрали). Дубль-RING игнорируется; ring-timeout 120 c, переарм на callee после Accept. Pre-accept мьют анонсируется пиру ДО OFFER (pendingCallSignals). Фоновые звонки: RING с неактивного инстанса → та же карточка; busy → авто-REJECT с фоновой; Accept → switchConnection (промоут без teardown); Decline → REJECT с фоновой; sendCallSignal через sessionMap.get(recordId). Аватары — в rosterStore.users (UserSummary), НЕ ServerMember. Статусные тосты («No answer.» и др.) — НАШИ добавки.

## Аттачи
Мозаика — порт AttachmentLayout.java; одиночная = квадрат с обрезанными полями (`singleTileBox`) — letterbox убран. Лайтбокс: зум к курсору + кламп (image-viewer-transform); Forward = ВСЁ сообщение (oak шлёт одиночный аттач — отступление); модалы через createPortal — position:fixed клипается transform-предком VirtualList. Edit-удаление картинок: PATCH `EditMessageRequest.attachments` — отсутствует = не трогать, список = заменить (валидация subset).

## Ник-модель (парный деплой с oak-server)
username = LOGIN (только Settings→Account «Change login»); nickname = НИК (unique, юникод-без-пробелов) = единственное отображаемое имя И единственный механизм упоминаний. MessageResponse не расширен — username остаётся ключом; `/topic/users` несёт displayName → `displayNameOf` перекрашивает всё через живой ростр; `SocialStore.applyUserRename` патчит снапшоты друзей/DM; сервер отдаёт lastMessageAuthorName = displayName. Гейты: self CHANGE_NICKNAME, чужой MANAGE_NICKNAMES+canActOn; 409 → «Nickname is already taken.». @-автодополнение и Add Friend — по никам; форвард шлёт originAuthorName = НИК.

## Шумодавы
Каталог `off | rnnoise | deepfilternet3 | dtln | speex | gate`, ДЕФОЛТ rnnoise (легаси apmEnabled=true → дефолт). Built-in WebRTC NS исключён; AEC/AGC всегда on; при движке noiseSuppression=false (двойной NS портит речь). Пайплайн `media/noise-suppression.ts`: raw → AudioWorklet → processed-трек (raw у владельца; micEnhancer до addTrack); звонки: RAW для teardown, PROCESSED в паблиш. Смена движка на живом голосе = rebuild от raw + replaceMicTrack БЕЗ перезахвата/ренего; упавший движок = publish RAW. RNNoise: кадры 480 + ПРАЙМИНГ-кадр (480 % 128 = 96 → иначе нули в середине потока). DFN3: пакет глотает ошибки ворклета → свой процессор поверх их glue (`npm run df3:glue`); wasm+модель локально; модель .bin-телом (Content-Encoding на .gz распаковывает браузер). DTLN: self-contained процессор (модели инлайн), litert-wasm через processorOptions, контекст 16 кГц. Speex/Gate vendored. NS-кнопка = меню движков, bypass НЕТ (юзер отверг).

## Инварианты (CSP, протокол, грабли)
`space-asset://` — read-only хендлер статики рендерера (path-traversal-гвард); движковые ассеты ТОЛЬКО через него: прод file:// не может fetch() свои файлы (origin null); нужен corsEnabled. CSP: connect-src += blob: (fetch(objectURL)) и space-asset:; script-src/worker-src += blob: (AudioWorklet) и 'wasm-unsafe-eval' (wasm в ворклете подчинён script-src). Тишина при заходе: замученный publisher НЕ ШЛЁТ RTP (track.enabled=false = нет пакетов) — трек получателя висит muted; joinVoice чистит только свои метки; сервер ре-паблишит меченых на каждом enter. Per-origin deviceId: id из dev-окна не существует в прод (file://) → OverconstrainedError с ПУСТЫМ message (логировать name); fallback System default. IPC: новое поле тост-payload обязано пробрасываться в ручном `toastBridge.show({...})` — типизация не ловит пропуск.

## Устойчивость к обрывам сети (#478, парный деплой)

Resync после STOMP-реконнекта: `onConnected(reconnected)` → `resyncAfterReconnect()`: presence (delta-буфер), voiceMembers, social/channels, read-states, ПОТОМ хвосты loaded-каналов через `MessageStore.mergeTail` (батч по id, один emit; новые строки — через `onLiveMessage`, считаются live). Порядок обязателен: read-states ДО хвостов (applySnapshot заменяет состояние, иначе сотрёт unread); дыра >100 сообщений остаётся — осознанно. Publisher-PC failed → rejoin-лестница (зеркало M4): `PublisherTransportError` → `handleVoiceSessionLost`; звонок после реконнекта реанонсирует пиру MIC/DEAFEN/CAM/SCREEN (`reannounceState`).

REST: `fetchWithRetries` — таймаут 20 с (не для upload/download); ретраи ТОЛЬКО идемпотентных (GET/PUT/DELETE + POST с idempotencyKey), бэкоф 500/1500; 5xx не ретраится; refresh-POST НИКОГДА не ретраится (replay ревокнет семью). Сообщения: `crypto.randomUUID()` на отправку → `CreateMessageRequest.idempotencyKey` (4-е поле), сервер отдаёт оригинал по ключу — POST /messages ретраится безопасно.

## Горячие клавиши + глобальный mute (#480)

Каталог Discord-совместимый: глобальные Toggle Mute/Deafen `Ctrl+Shift+M/D`, NS `Ctrl+Shift+N`; локальные Next/Prev Channel `Alt+↓/↑`, поиск `Ctrl+F`, диагностика `Ctrl+Shift+F12`. ОСОЗНАННЫЙ ОТКАЗ от дискордовых accept/decline-call: OS-wide хорд съедает клавишу во всей ОС (Ctrl+Enter — перенос строки композера; Esc занят модалками). ИНВАРИАНТ: глобальный хорд ВСЕГДА через OS-hook (RegisterHotKey не пускает клавишу в приложение и в фокусе) — локальный keydown матчит только scope=local (иначе двойной тоггл); bare-клавиша в полях ввода = печать; занятый чужим процессом хорд Windows фейлит молча (статус taken → амбер-бейдж). `resolveKeybinds`: дефолты⊕stored, «»=unbound, unknown id дроп (forward-compat). Диспетчер: `voiceSurfaceFor` (call бьёт room; ringing-in = room; none = тишина); accept/decline = `callCardAction` (общее с кнопками тоста); шаг каналов — TEXT-каналы, no-op в dmMode. Свип-кью в самих toggle-функциях: мут 500↔900 Гц, deafen 280↔480; звуковые семейства попарно не пересекаются. Хранение `ClientSettings.keybinds`; секция не staged (per-row pending); на время записи OS-хорды suspend (занятые хорды иначе не слышны).

## Поиск по сообщениям + окно ?around= (#481, парный деплой)

Матчинг ПОДСТРОКОЙ: ILIKE + pg_trgm-GIN (tsvector отвергнут — не ищет подстроки, не живёт в H2); индексы — ручная psql-миграция. Сервер: `GET /api/search/messages` (q/channelId/author/beforeId/limit; `{total, results}`, newest-first); история += `aroundId` (окно с центром; 404 на чужой) и `afterId` (ASC); server-side ack монотонный. Скоуп: канал ↔ «Everywhere»; DM в серверо-широкий НЕ входят.

Инварианты клиента: `applySnapshotAround` ЗАМЕНЯЕТ список канала; `applyLive` при around дропает id>last (дыра окно↔хвост; своё отправленное не появляется — Discord-фейсфул); `mergeTail` → []; around-переход = один патч activeAround БЕЗ loadHistory+ack (ack середины обнулил бы unread); `ackActiveChannel` гейтится isAroundWithoutTail (локальный ack НЕ монотонен — закрывает все пути); 404 → loadHistory + тост. UX: правая колонка постоянна (свап ростер↔результаты); Esc закрывает и чистит; dmMode — колонка только при открытом поиске; from: — автокомплит по никам (на wire username); `<mark>`-подсветка — indexOf без regex (LIKE-метасимволы бесплатны); клик = openChannelAtMessage.

## Push-to-talk — скип (юзер-решение)

PTT требует keyup, `globalShortcut` даёт только keydown → нужен низкоуровневый хук ОС. НЕ делать: приватность-паттерн (хук видит все нажатия везде — «кейлоггер»); стабильность (тупящий колбэк → Windows молча отцепляет хук); первый НАТИВНЫЙ модуль (ABI/prebuilds/пересборка на мажорах Electron — сейчас ноль). «Мутиться в игре» закрыт toggle-mute (globalShortcut — системный сервис, клавиш не видит). Возврат: если нужно именно удержание → uiohook-napi (+мышиные кнопки, self/mod-мьюты, индикация).

## Вычитание своего звука из loopback (#483) — NO-GO

Цель: десктоп в шаре БЕЗ нашего голосового канала (в Discord нет). Архфакт: плayout НЕ через WebAudio-граф — remote-треки играют голыми `<audio>` (урок M0), референс = реконструкция. Спайк (bulk-дилэй FFT-кросскорреляцией + NLMS; ворклет — ручная синхронизированная копия чистого DSP, прецедент rnnoise) дал GO (34–48 дБ), продакшн — NO-GO: живьём 2.4 дБ после 8 итераций. Корень — топология Chromium: несколько доменов часов на пути, согласование не сэмпл-стабильно; каждый слой ломал адаптивное состояние по-новому. УРОК: спайк обязан проверять продакшн-топологию путей — самотест её не моделирует. Откат: шары публикуют СЫРОЙ loopback. Осталось: `LOOPBACK_AUDIO_CONSTRAINTS` (NS/AGC/echoCancellation:false) на всех 4 захватах loopback — реальный фикс качества шар-звука (Chromium гнал loopback через свой APM); референс-шины RoomAudio/NotificationHub mixBus; MessagePort: `addEventListener("message")` не стартует порт — `onmessage`/`port.start()`.

## WASAPI process-loopback через koffi (#485) — GO + продакшн

oak делал через JNA (runtime-FFI без своего C++); Node-эквивалент — koffi (prebuilt N-API FFI, первый сторонний prebuilt-нативный деп, своих нативных модулей ноль). GO: exclude-self доказан живьём — клиент акустически невидим, внешний звук пишется чисто. Обвязка: guarded require (win32 + build ≥ 19041), дрен таймером без нативного потока, COM-хендлер один на процесс (правило oak/vlcj); IPC `space-sysaudio:*`; инжектор-ворклет → track. ГРАБЛИ: register хочет `koffi.pointer(proto)`; `koffi.view()` в Electron фаталит процесс (в node разрешён) → модуль без view: encode/decode, memcpy в Buffer, memcmp. Встройка: на шве шара `acquireNativeShareAudioTrack(sourceId?)` (фейл = null) → display-аудио `.stop()`, в sfu/peer-call `new MediaStream([displayVideo, nativeTrack])` — подмена прозрачна (стерео-мунж as-is). Экраны = EXCLUDE-self (десктоп минус наш процесс); окна = INCLUDE per-app (HWND→PID через user32) — oak-парити, окна не просят Chromium-аудио. Фолбэк: экраны → сырой loopback, окна → video-only — шар никогда не ломается из-за фичи. Teardown → releaseNativeShareAudio().
